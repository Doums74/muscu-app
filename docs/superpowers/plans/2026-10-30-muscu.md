# Muscu — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Une web app installable sur Pixel 7 qui guide les séances de musculation série par série et fait progresser le programme, avec une séance préparée par Claude sur le Mac et des garde-fous codés.

**Architecture:** Toute la logique d'entraînement est faite de fonctions pures dans `src/domaine/`, testées avec Vitest et partagées entre l'app et un script de validation lancé sur le Mac. L'app (Preact) lit et écrit trois fichiers JSON dans le dépôt privé `muscu-data` via l'API Contents de GitHub, avec un cache `localStorage` et une file d'attente hors ligne. Un skill Claude Code `prepare-seance` côté Mac écrit `prochaine-seance.json` puis lance le validateur avant de pousser.

**Tech Stack:** Vite 7, TypeScript 5 (strict), Preact 10 + hooks, Vitest 3 + @testing-library/preact + jsdom, vite-plugin-pwa, tsx (script Mac), GitHub Pages via GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-30-muscu-design.md`

## Global Constraints

- Toute l'interface et tous les messages utilisateur sont en **français**. Identifiants de code en français, sans accents (`seance`, `exercice`, `charge`).
- Unités : kg pour les charges, secondes pour les repos et les exercices tenus.
- Plages de repos (s) : `explosivite` 90–120, `force` 120–180, `unilateral` 60–90, `gainage` 45–60.
- Bloc = 18 séances principales (A/B/C), semaine du bloc = `floor(n / 3) + 1`. Semaine 6 = allégée. Semaine 1 = calibrage (charges de départ du programme).
- Augmentation max d'une séance à l'autre : `max(increment, arrondiInf(charge × 0.05, increment))`.
- Aucune donnée personnelle (âge, poids, taille, token) dans le dépôt public `muscu-app`.
- Les liens vidéo sont des recherches YouTube : `https://www.youtube.com/results?search_query=<nom+technique>`. Aucune URL de vidéo inventée.
- Le token GitHub n'est stocké que dans `localStorage` du téléphone (clé `muscu.config`), jamais dans le code ni dans un dépôt.
- Coût 0 € : aucun service payant, aucune clé d'API.

## Review Focus

- **Rechargement ou fermeture de l'app en pleine séance** → la séance reprend à la série en cours avec les séries déjà saisies (Task 9, test `reprend une seance en cours apres rechargement`).
- **Pas de réseau à la fin de la séance** → la séance est gardée en file d'attente, envoyée au prochain lancement en ligne, sans doublon dans `historique.json` (Task 7, tests `met en file d'attente hors ligne` et `ne duplique pas une seance deja envoyee`).
- **`prochaine-seance.json` déjà faite ou d'un ancien bloc** → elle n'est pas rejouée ; l'app génère la séance locale (Task 4, test `ignore une seance preparee deja realisee ou d'un autre bloc`).
- **Écran verrouillé ou app en arrière-plan pendant le repos** → au retour, le minuteur affiche le temps restant réel, et le repos est fini s'il est dépassé (Task 9, test `minuteur base sur l'horloge reelle`).
- **Token expiré ou invalide (401)** → message clair sur l'accueil, et l'app reste utilisable avec le cache (Task 7, test `token invalide renvoie le cache et une erreur lisible`).

### Task 3: Garde-fous

**Files:**
- Create: `src/domaine/gardefous.ts`
- Test: `tests/domaine/gardefous.test.ts`

**Interfaces:**
- Consumes: `trouverExercice`, `augmentationMax`, `arrondiInf`, `derniereFois`.
- Produces:
  - `PLAGES_REPOS: Record<Bloc, [number, number]>` (valeurs des Global Constraints)
  - `validerSeance(brut: unknown, historique: SeanceRealisee[]): { seance: SeancePrevue | null; avertissements: string[] }`
  - `validerProgramme(brut: unknown): { programme: Programme | null; erreurs: string[] }`

Règles de `validerSeance`, dans l'ordre (chaque correction ajoute un avertissement en français qui nomme l'exercice) :
1. Forme invalide (champs requis manquants ou de mauvais type) → `seance: null`.
2. Exercice inconnu de la bibliothèque → retiré. S'il ne reste aucun exercice → `seance: null`.
3. Séries limitées entre 1 et 6 ; reps entre 1 et 30 (`mesure: 'reps'`) ou entre 5 et 120 (`mesure: 'secondes'`).
4. Repos ramené dans `PLAGES_REPOS[bloc]`.
5. Charge > `chargeMaxDerniereFois + augmentationMax(...)` → ramenée à ce plafond. Pas de plafond sans historique pour l'exercice (calibrage).
6. `semaine === 6` → charge ≤ `arrondiInf(chargeMaxDerniereFois × 0.9, increment)`.
7. Charge négative → 0. Exercice à `increment === 0` → charge 0.

`validerProgramme` : `seances` A, B, C, D présentes ; tous les ids connus ; repos dans les plages ; `repsMin ≤ repsMax` ; A, B et C contiennent chacune au moins un exercice de chaque bloc, dans l'ordre explosivite → force → unilateral → gainage ; D contient au moins un exercice `gainage`. Chaque violation → `erreurs`, et `programme: null` s'il y a au moins une erreur.

### Task 4: Progression locale (double progression) et choix de la séance

**Files:**
- Create: `src/domaine/progression.ts`
- Test: `tests/domaine/progression.test.ts`

**Interfaces:**
- Consumes: Tasks 2 et 3.
- Produces:
  - `genererSeanceLocale(programme: Programme, historique: SeanceRealisee[], type: TypeSeance, maintenant: Date): SeancePrevue` (`source: 'locale'`, `id: "<AAAA-MM-JJ>-<type>"`)
  - `choisirSeance(programme: Programme, prochaine: SeancePrevue | null, historique: SeanceRealisee[], maintenant: Date): { seance: SeancePrevue; avertissements: string[] }`

Règles par exercice du programme pour `genererSeanceLocale` (dernière réalisation via `derniereFois`) :
- Jamais fait → `chargeDepart`, cible `repsMax` sur chaque série.
- Toutes les séries prévues faites avec `reps ≥ repsMax` → charge + `increment` (un seul incrément).
- Exercice à `increment === 0` : charge 0, cible = meilleure perf de la dernière fois + 1 (reps) ou + 5 (secondes).
- Les **2** dernières réalisations ont chacune une série avec `reps < repsMin` → charge `arrondiProche(charge × 0.9, increment)`.
- Sinon → même charge.
- `semaine === 6` → `series − 1` (minimum 1) et charge `arrondiInf(charge × 0.9, increment)`.

`choisirSeance` : utilise `prochaine` passée par `validerSeance` si elle existe, si `prochaine.blocId === programme.blocId`, si son `id` n'est pas dans l'historique, et si la validation ne renvoie pas `null`. Sinon, renvoie `genererSeanceLocale(programme, historique, prochainType(...), maintenant)`.

### Task 7: Stockage GitHub, cache et file d'attente hors ligne

**Files:**
- Create: `src/stockage/local.ts`, `src/stockage/github.ts`, `src/stockage/depot.ts`
- Test: `tests/stockage/github.test.ts`, `tests/stockage/depot.test.ts`

**Interfaces:**
- Produces:
  - `local.ts` : `interface Stockage { lire<T>(cle: string): T | null; ecrire(cle: string, valeur: unknown): void; effacer(cle: string): void }`, `stockageNavigateur: Stockage` (localStorage, JSON). Clés : `muscu.config`, `muscu.cache`, `muscu.attente`, `muscu.enCours`.
  - `github.ts` : `interface Config { proprietaire: string; depot: string; token: string }` ; `class ErreurGitHub extends Error { statut: number }` ; `class ClientGitHub { constructor(config: Config, fetchFn?: typeof fetch); lire<T>(chemin: string): Promise<{ contenu: T; sha: string } | null>; ecrire(chemin: string, contenu: unknown, sha: string | null, message: string): Promise<string> }`. `lire` renvoie `null` sur 404. Base64 décodé en UTF-8 (`TextDecoder`), encodé avec `TextEncoder`. En-têtes : `Authorization: Bearer <token>`, `Accept: application/vnd.github+json`.
  - `depot.ts` :
    - `interface Etat { programme: Programme | null; prochaine: SeancePrevue | null; historique: SeanceRealisee[]; horsLigne: boolean; erreur: string | null }`
    - `chargerEtat(client: ClientGitHub, stockage: Stockage): Promise<Etat>` → lit `programme.json`, `prochaine-seance.json` et `historique.json`, puis met à jour `muscu.cache`. En cas d'échec réseau ou d'`ErreurGitHub`, renvoie le cache, avec `horsLigne: true` et un `erreur` lisible (401 → « Clé GitHub invalide ou expirée — mets-la à jour dans Réglages. »). L'historique renvoyé inclut aussi les séances de `muscu.attente`.
    - `enregistrerSeance(client, stockage, s: SeanceRealisee): Promise<'envoyee' | 'en-attente'>` → ajoute `s` à `muscu.attente`, puis appelle `synchroniser`.
    - `synchroniser(client, stockage): Promise<number>` → pour la file d'attente : relit `historique.json`, ajoute les séances dont l'`id` est absent, fait un PUT avec le sha. En cas de 409 ou 422 (sha périmé), relit et réessaie une fois. Vide `muscu.attente` seulement après le succès. Renvoie le nombre de séances envoyées.
